# 本地生活服务点评平台 - 产品需求文档

## Overview
- **Summary**: 构建一个简化版的本地生活服务点评类网站应用，包含用户端、商户管理后台、平台管理后台三个子系统，实现商户浏览搜索、用户点评互动、预约服务、商户入驻审核等核心功能。
- **Purpose**: 为用户提供本地商户信息查询与点评交流平台，为商户提供线上展示与预约管理渠道，为平台提供内容管控与商户治理能力。
- **Target Users**: 
  - C端普通用户：查找商户、浏览点评、发布评价、预约服务
  - B端商户：申请入驻、维护门店信息、管理预约订单
  - 平台管理员：审核商户资质、管控违规内容

## Goals
- 构建前后端分离的完整Web应用，支持移动端与桌面端响应式访问
- 实现商户浏览、搜索、筛选、详情展示的完整用户路径
- 建立三级用户体系（普通用户/商户/管理员）的权限隔离
- 完成点评发布、点赞、预约提交与处理等核心互动功能
- 提供商户入驻申请与平台审核的闭环流程
- 确保系统可本地一键部署运行，附带完整的初始化脚本与文档

## Non-Goals
- 不实现在线支付、订单结算等交易功能
- 不实现实时聊天/消息推送等长连接功能
- 不实现复杂的推荐算法，仅支持基础排序筛选
- 不接入真实短信服务，验证码采用模拟方式
- 不实现复杂的地图导航，仅展示静态地址文本
- 不进行生产级部署配置（如负载均衡、CDN、集群等）

## Background & Context
- 项目为全新开发，无历史代码依赖
- 采用轻量化技术栈，优先考虑开发效率与可维护性
- 技术选型：
  - 前端：Vue 3 + Vite + Pinia + Vue Router + Element Plus
  - 后端：Node.js + Express + Sequelize ORM
  - 数据库：MySQL 8.0+
  - 认证：JWT Token 机制
  - 图片存储：本地文件系统

## Functional Requirements

### 用户端功能
- **FR-1**: 用户可按品类、区域、评分筛选商户列表，支持关键词搜索
- **FR-2**: 商户详情页展示地址、营业时间、联系电话、环境图片、评分统计、点评列表
- **FR-3**: 用户通过手机号+模拟验证码注册/登录，维护个人信息
- **FR-4**: 用户可收藏/取消收藏商户，查看收藏列表
- **FR-5**: 用户可发布点评（1-5星评分、≤1000字文字、≤3张配图）
- **FR-6**: 用户可对他人点评点赞/取消点赞
- **FR-7**: 用户可选择日期时段提交商户到店预约

### 商户后台功能
- **FR-8**: 商户提交资质信息（营业执照、门店信息等）申请入驻
- **FR-9**: 商户通过审核后可编辑门店信息、上传环境图、更新营业时间
- **FR-10**: 商户查看用户预约申请，标记预约状态（待确认/已确认/已完成/已取消）

### 平台后台功能
- **FR-11**: 平台管理员审核商户入驻申请（通过/驳回）
- **FR-12**: 平台管理员可下架违规点评，查看处理用户举报

### 系统级功能
- **FR-13**: 基于角色的访问控制（普通用户/商户/管理员三级权限）
- **FR-14**: 接口跨域处理与环境变量配置隔离
- **FR-15**: 数据库初始化脚本（表结构+测试数据）

## Non-Functional Requirements
- **NFR-1**: 响应式布局：桌面端（≥1200px）、平板（768-1199px）、移动端（≥375px）均正常显示
- **NFR-2**: 页面首屏加载时间 ≤ 3秒（本地开发环境）
- **NFR-3**: 核心接口响应时间 ≤ 500ms（本地开发环境，单用户）
- **NFR-4**: 支持 Chrome、Edge、Safari 最新两个主版本浏览器
- **NFR-5**: 代码结构分层清晰，前后端均遵循 MVC/分层架构规范
- **NFR-6**: 接口参数校验完整，错误提示友好统一

## Constraints
- **Technical**:
  - 必须使用 MySQL 作为主数据库，不得使用其他数据库替代
  - 前后端分离部署，通过 RESTful API 通信
  - 认证必须使用 JWT 机制
- **Business**:
  - 点评内容限制：文字≤1000字，图片≤3张
  - 评分范围：1-5星整数
  - 验证码固定为 6 位数字（模拟发送，无需真实短信）
- **Dependencies**:
  - 本地需安装 Node.js ≥ 18、MySQL ≥ 8.0

## Assumptions
- 用户手机号注册时验证码固定为 `123456`（无需真实短信服务）
- 默认预置一个平台管理员账户（admin / admin123）
- 默认预置若干测试商户与点评数据用于开发调试
- 图片上传存储于后端 `uploads/` 目录，通过静态资源服务访问
- 预约时段为每日 09:00-21:00，每小时一个时段

## Acceptance Criteria

### AC-1: 商户列表筛选与搜索
- **Type**: `rule`
- **Given**: 用户访问商户列表页，系统中存在多品类多区域的测试商户数据
- **When**: 用户选择品类筛选条件（如"餐饮"），或输入关键词（如"火锅"），或选择评分区间（如"4分以上"）
- **Then**: 列表仅展示符合所有筛选条件的商户，分页正常，总数显示正确
- **Pass Condition**: 组合筛选结果与数据库查询条件一致，搜索关键词匹配商户名称/地址/品类字段
- **Evidence**: 接口返回数据断言 + 前端列表渲染验证截图

### AC-2: 商户详情页信息完整展示
- **Type**: `rule`
- **Given**: 系统存在至少1条完整的商户数据（含地址、电话、营业时间、环境图、点评）
- **When**: 用户进入该商户详情页
- **Then**: 页面完整展示商户名称、品类标签、地址、电话、营业时间、环境图轮播、平均评分、点评数量、点评列表（每条含评分、文字、图片、点赞数、发布时间、用户昵称）
- **Pass Condition**: 详情页所有字段与数据库记录一一对应，点评列表分页加载正常
- **Evidence**: 前端页面渲染截图 + 接口响应数据对比

### AC-3: 用户手机号注册登录
- **Type**: `rule`
- **Given**: 用户未登录状态，访问登录/注册页
- **When**: 用户输入手机号 + 验证码 `123456` 提交
- **Then**: 新用户自动注册并登录，老用户直接登录，返回 JWT Token，本地持久化存储，用户信息展示正确
- **Pass Condition**: 连续3次登录流程均成功，重复注册同一手机号不重复创建用户，Token 过期后需重新登录
- **Evidence**: 登录接口响应 + 前端路由鉴权跳转验证

### AC-4: 用户收藏商户
- **Type**: `rule`
- **Given**: 用户已登录，浏览任意商户详情页
- **When**: 用户点击"收藏"按钮，再点击"取消收藏"，进入"我的收藏"页
- **Then**: 收藏状态正确切换，收藏列表实时更新，取消后不再出现在收藏列表中
- **Pass Condition**: 收藏/取消收藏接口调用成功，数据库关联表记录增删正确，前端状态无缓存错误
- **Evidence**: 接口调用日志 + 数据库记录变化 + 收藏页截图

### AC-5: 发布点评功能
- **Type**: `rule`
- **Given**: 用户已登录，进入商户详情页
- **When**: 用户选择5星评分，输入500字评价文字，上传3张图片后提交
- **Then**: 点评发布成功，出现在该商户点评列表首位，商户平均评分重新计算，用户可在"我的点评"中查看
- **Pass Condition**: 文字超1000字或图片超3张时前端+后端均拦截，评分不在1-5区间时拦截
- **Evidence**: 正常发布流程测试 + 边界条件拦截测试

### AC-6: 点评点赞功能
- **Type**: `rule`
- **Given**: 用户已登录，商户详情页存在其他用户的点评
- **When**: 用户对某条点评点击点赞，再次点击取消点赞
- **Then**: 点赞数正确±1，用户已点赞状态有视觉区分，重复点赞不重复计数
- **Pass Condition**: 点赞接口幂等，数据库记录正确，刷新页面后状态不变
- **Evidence**: 点赞操作前后计数变化对比 + 刷新验证

### AC-7: 用户提交预约
- **Type**: `rule`
- **Given**: 用户已登录，进入商户详情页
- **When**: 用户选择日期+时段，填写联系电话和备注，提交预约
- **Then**: 预约提交成功，状态为"待确认"，用户可在"我的预约"查看记录，同一时段同一商户不重复提交成功（可选提示已约满）
- **Pass Condition**: 时段选择控件禁用过期时段，提交后数据写入预约表，状态流转正确
- **Evidence**: 预约表单提交 + 预约列表展示 + 数据库记录

### AC-8: 商户入驻申请与审核
- **Type**: `rule`
- **Given**: 平台管理员已登录后台，存在未审核的商户入驻申请
- **When**: 商户端提交入驻申请（含营业执照号、门店名称、地址、品类、联系人信息）→ 管理员在平台后台审核通过
- **Then**: 商户状态从"待审核"变为"已通过"，商户账号获得商户后台登录权限，该商户对C端用户可见
- **Pass Condition**: 审核驳回后商户状态变为"已驳回"，附带驳回原因，商户可修改后重新提交
- **Evidence**: 商户申请→管理员审核→商户端状态变更 完整流程截图

### AC-9: 商户信息维护
- **Type**: `rule`
- **Given**: 商户已通过审核并登录商户后台
- **When**: 商户编辑门店名称、营业时间、上传新环境图后保存
- **Then**: 商户信息更新成功，C端商户详情页实时展示最新信息，环境图增删正确
- **Pass Condition**: 必填项为空时校验拦截，营业时间格式不合法时拦截
- **Evidence**: 编辑前后信息对比 + C端展示同步验证

### AC-10: 商户预约处理
- **Type**: `rule`
- **Given**: 商户已登录后台，存在"待确认"状态的用户预约
- **When**: 商户对该预约点击"确认"，随后标记为"已完成"
- **Then**: 预约状态依次变为"已确认"→"已完成"，用户端预约状态同步更新，状态不可逆（已完成不可变回待确认）
- **Pass Condition**: 状态流转符合有限状态机：待确认→已确认/已取消；已确认→已完成/已取消
- **Evidence**: 状态流转操作记录 + 用户端同步验证

### AC-11: 平台违规点评管控
- **Type**: `rule`
- **Given**: 平台管理员已登录后台，系统中存在违规点评
- **When**: 管理员对某条点评点击"下架"
- **Then**: 该点评在C端商户详情页不再展示，点评列表状态标记为"已下架"，管理员可在后台查看所有下架记录
- **Pass Condition**: 下架操作有操作人记录与时间戳，已下架点评不参与商户平均评分计算
- **Evidence**: 下架操作 + C端展示消失 + 评分重新计算验证

### AC-12: 响应式布局兼容性
- **Type**: `rubric`
- **Dimension**: 多端适配完整性
- **Scale**: 1-5
- **Anchors**: 
  1 = 仅桌面端正常，移动端严重错乱；
  3 = 桌面端+移动端基本可用，部分页面存在排版问题但不影响使用；
  5 = 375px/768px/1200px 三个断点下所有核心页面（列表/详情/登录/个人中心/后台首页）布局无错乱，交互控件可正常点击
- **Pass Threshold**: >= 4
- **Evidence**: Chrome DevTools 设备模拟三断点下的截图对比

### AC-13: 代码结构与可维护性
- **Type**: `rubric`
- **Dimension**: 工程化质量
- **Scale**: 1-5
- **Anchors**:
  1 = 前后端代码混杂，无分层，无注释；
  3 = 前后端分离有基础目录结构，核心模块有简单注释，部分接口缺少参数校验；
  5 = 后端采用 Controller/Service/Model 三层架构，前端采用组件化，API 层封装统一，环境变量配置隔离，接口参数校验完整，错误处理统一，README 部署说明清晰可执行
- **Pass Threshold**: >= 4
- **Evidence**: 目录结构树 + 关键文件代码检查 + 部署文档评审

### AC-14: 核心流程端到端通过率
- **Type**: `rule`
- **Given**: 系统已按文档完成本地部署，数据库已初始化测试数据
- **When**: 依次执行以下流程：用户注册登录→浏览商户→筛选搜索→查看详情→收藏商户→发布点评→点赞点评→提交预约；商户端登录→审核预约；管理员登录→审核商户入驻→下架违规点评
- **Then**: 所有流程无阻塞，数据正确流转，无未处理异常崩溃
- **Pass Condition**: 每个核心流程 3 次执行通过率 100%，无业务逻辑错误
- **Evidence**: 端到端测试执行记录或人工操作录屏/截图
